# 문제 정의

현장 상황과 풀려는 최적화 문제를 정리한 문서입니다. 새로운 정보가 들어올 때마다 고쳐 나갑니다.

- 마지막 수정: 2026-09-23
- 지명 대신 기호를 씁니다. 학원은 A·B·C, 하원 목적지는 ①~④입니다.

## 1. 현장 상황

### 학원

| 학원 | 반 | 위치 | 비고 |
|---|---|---|---|
| A | 초등반 | 북쪽, 목적지 ② 바로 옆 | |
| B | 초·중등반 | 남동쪽 읍내, 목적지 ④ 가까이 | C와 횡단보도 하나 사이 |
| C | 중·고등반 | 남동쪽 읍내, 목적지 ④ 가까이 | B와 횡단보도 하나 사이 |

### 수업이 끝나는 방식

- 과목 단위로 수강합니다.
- 중·고등반은 같은 강의를 들으면 대부분 비슷한 시각에 끝납니다.
- 초등반은 여러 학생이 동시에 각자 진도대로 공부하고, 할당량을 마치면 바로 끝납니다. 두 과목(예: 수학·영어)을 들으면 한 과목이 끝나는 대로 다음 과목으로 넘어갑니다.
- 그래서 끝나는 시각은 학원마다 다르고, 특히 초등반은 매우 불규칙합니다.
- 한 번에 몇 명이 나올지도 그때그때 달라서 미리 알 수 없습니다.

### 셔틀

- 9인승 스타렉스 1대를 세 학원이 함께 씁니다. 운전석을 빼면 학생은 최대 8명으로 보고 있습니다(확인 중).
- 하원에만 쓰고, 등원에는 쓰지 않습니다.
- 주로 초·중등 학생이 탑니다. 중·고등 학생은 거의 타지 않습니다.
- 목적지가 학원 바로 옆인 학생(A→②, B·C→④)은 타지 않습니다.

### 지금 운행 방식

1. 수업이 끝난 학생이 생기면, 선생님이 단톡방에 "○○시에 △△로 가는 학생 있음"을 올립니다.
2. 기사님이 이 요청을 보고 지점을 돌며 태우고 내려 줍니다.

정해진 시간표 없이, 요청이 들어올 때마다 대응하는 방식입니다.

### 하원 목적지

| 목적지 | 종류 | 셔틀을 타는 학생 |
|---|---|---|
| ① | 마을 | A, B·C 학생 모두 |
| ② | 아파트 단지, A 바로 옆 | B·C 학생 |
| ③ | 아파트 단지, B·C에서 동쪽으로 조금 | A 학생 (B·C 학생은 확인 중) |
| ④ | 아파트 단지, B·C 가까이 | A 학생 |

### 위치와 이동 시간

![학원과 하원 목적지 배치 개념도](images/sites.svg)

기사님 기준으로 차로 걸리는 시간입니다.

| 구간 | 시간 |
|---|---|
| A ↔ B·C | 약 4~6분 |
| A ↔ ① | 약 10분 |
| B·C ↔ ① | 약 10분 |
| 나머지 구간 | 확인 중 |

지도상 직선거리로는 ①이 A↔B·C 거리의 2.7~3.2배 떨어져 있지만, 차로는 약 2배입니다. ①로 가는 길이 빠른 것으로 보입니다.

셔틀이 서는 곳은 세 무리로 나뉩니다.

- **북쪽 무리:** 학원 A, 목적지 ②
- **남동쪽 무리:** 학원 B·C, 목적지 ③·④
- **서쪽 끝:** 목적지 ①

두 무리 사이에는 양쪽 방향 수요가 있습니다. A 학생은 남동쪽(③·④)으로, B·C 학생은 북쪽(②)으로 갑니다. 그래서 A와 B·C를 오가는 한 번의 운행으로 양쪽 학생을 함께 태울 수 있습니다.

## 2. 풀려는 문제

끝나는 시각과 인원을 미리 알 수 없으므로, 하루치 시간표를 미리 짜는 문제가 아닙니다. 운행 중에 계속 내려야 하는 판단을 돕는 문제입니다.

### 매번 정해야 하는 것

- 요청이 들어왔을 때 바로 출발할지, 조금 기다렸다가 같은 방향 학생과 묶어서 갈지
- 어느 학원을 먼저 들르고, 어떤 순서로 내려 줄지
- 운행이 없을 때 어디서 기다릴지

예를 들어 A와 B·C에 모두 ①로 갈 학생이 있을 때, 따로 다녀오면 왕복 약 20분씩 모두 40분쯤 걸립니다. A → B·C → ① → 복귀로 묶으면 25분쯤이면 됩니다. 대신 먼저 탄 학생은 더 오래 타고, 나중에 탈 학생은 셔틀이 올 때까지 기다려야 합니다.

### 지켜야 할 것

- 한 번에 태우는 학생은 좌석 수를 넘을 수 없습니다.
- 학생은 수업이 끝난 뒤에만 탈 수 있습니다.
- 차가 한 대라서 한 번에 한 곳만 갈 수 있습니다.
- (확인 중) 학생이 기다리거나 차에 타 있는 시간의 상한

### 줄이고 싶은 것 (우선순위 확인 중)

- 학생이 수업을 마치고 집에 도착하기까지 걸리는 시간 (기다림 + 탑승)
- 기사님이 운전하는 총 시간
- 선생님과 기사님이 단톡방으로 조율하는 수고

### 문제 유형

최적화 분야에서는 요청이 실시간으로 들어오는 **동적 합승 배차 문제(dynamic dial-a-ride problem)** 에 가깝습니다. 차량이 1대이고 서는 곳이 적어서, 요청이 모두 주어졌을 때 가장 좋은 경로를 찾는 계산은 어렵지 않습니다. 어려운 부분은 앞으로 들어올 요청을 모르는 채로 "지금 갈지, 기다릴지"를 정하는 판단입니다.

## 3. 접근 방법 (제안)

1. **지난 요청 기록 모으기:** 단톡방 기록에서 요청 시각, 학원, 목적지, 인원을 뽑아 요일·시간대별 패턴을 봅니다. 이름 같은 개인정보는 지우고, 원본은 저장소에 올리지 않습니다.
2. **운행 규칙 비교:** 같은 요청 기록으로 여러 운행 규칙을 시뮬레이션해서 학생 대기 시간, 탑승 시간, 운전 시간을 비교합니다.
   - **지금 방식:** 요청이 오면 바로 대응
   - **묶어 가기:** 같은 방향 요청을 정해진 시간까지 기다렸다가 함께 출발
   - **정시 순환:** A와 B·C를 정해진 간격으로 돌고, ①은 정해진 시각에 모아서 운행
3. **실시간 배차 도우미:** 가장 나은 규칙을 바탕으로, 선생님이 요청을 입력하면 기사님에게 다음 운행을 추천하는 간단한 화면을 만듭니다.

## 4. 확인할 것

- [ ] 9인승이 운전석 포함인지 (학생 최대 8명인지)
- [ ] 나머지 구간 이동 시간: B·C↔③, A↔③, A↔④, ①↔③ 등
- [ ] B·C 학생도 ③으로 갈 때 셔틀을 타는지
- [ ] 초등반 학생이 과목을 바꿀 때 다른 지점으로 옮기는지, 옮긴다면 셔틀로 이동하는지
- [ ] 셔틀 운행 시간대 (몇 시부터 몇 시까지)
- [ ] 단톡방 기록을 내보낼 수 있는지, 얼마나 쌓여 있는지
- [ ] 하루 요청 건수와 한 번에 타는 인원의 대략적인 범위
- [ ] 가장 불편한 점: 학생 대기, 기사님 동선, 단톡방 조율 중 무엇인지
- [ ] 목적지마다 한 곳에서만 내리는지 (특히 ① 마을)
- [ ] B·C 학생을 한 곳에서 한 번에 태울 수 있는지
